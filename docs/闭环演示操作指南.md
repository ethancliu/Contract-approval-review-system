## 三、演示脚本逐步解读（11 个步骤）

| 步骤 | 内容 | 验证要点 |
| --- | --- | --- |
| **0** | 服务健康检查 | 主服务与模拟审批系统均可用，规则库 16 条 |
| **1** | **工具 1｜待办拉取** | 拉取 8 条待办，每条必含审批编号 / 标题 / 申请人 / 申请时间 / 附件数量 |
| **2** | **去重验证** | 连续两次同步：第二次 `created = 0`，证明按审批编号去重生效，绝不重复创建任务 |
| **3** | **工具 2｜审批详情** | 展示基础信息、表单数据、附件信息、当前处理状态四项齐全 |
| **4** | **工具 3｜附件下载** | 返回本地存储路径 + 文件大小 + MD5 校验值 + 下载状态 |
| **5** | **工具 4｜文档解析** | 展示 16 项字段（8 基础 + 8 条款），每项含字段值 / 原文片段 / 位置定位 / 提取状态 / 失败原因 |
| **6** | **工具 5｜规则审查** | 命中 8 条规则（高 3 / 中 5 / 低 0），总风险等级「高」，每条含证据原文 + 证据位置 + 处理建议 |
| **7** | **工具 6｜结果保存** | 返回 `review_id`，审查结果 / 命中规则 / 风险摘要 / 关注点全部入库 |
| **8** | **工具 7｜评论回写** | 回写状态 `success`，打印审批评论区实际收到的完整意见全文（六段式） |
| **9** | **一键闭环（全量）** | 8 个任务批量走完闭环，输出任务状态 / 回写状态 / 风险等级 / 命中数 / 阻塞原因总表 |
| **10** | **异常阻塞与人工重试** | 见 [第七节](#七异常恢复演示人工重试) |
| **11** | **结果总览** | 任务数、状态分布、风险分布、启用规则数、累计命中数 |

### 关键中间结果（预期值）

**步骤 5 —— 结构化字段提取（以 HTSP20261009002 为例）**

```
字段提取完整度：14/16
合同金额：1200000元      位置：第1页 第3段 第1行（字符偏移 …，来源：Word文档）
币种：人民币（CNY）       位置：第1页 第3段 第1行（字符偏移 …，来源：Word文档）
生效时间：2026-10-15      位置：第1页 第2段 第1行（字符偏移 …，来源：Word文档）
到期时间：2027-10-14      位置：第1页 第2段 第1行（字符偏移 …，来源：Word文档）
```

**步骤 6 —— 规则命中（8 条）**

| # | 等级 | 规则 | 命中证据摘要 |
| --- | --- | --- | --- |
| 1 | 高 | 数据处理合规风险 `R-DATA-001` | 将部分数据传输至境外服务器进行处理 |
| 2 | 高 | 知识产权归属风险 `R-IP-001` | 全部技术成果、软件著作权均归乙方所有 |
| 3 | 高 | 预付款比例异常 `R-PAY-001` | 支付合同总金额的 50% 作为预付款（阈值 30%） |
| 4 | 中 | 验收标准缺失 `R-ACCEPT-001` | 全文未检出「验收条款」 |
| 5 | 中 | 保密条款缺失 `R-CONF-001` | 全文未检出「保密条款」 |
| 6 | 中 | 管辖地风险 `R-LEGAL-001` | 向乙方所在地有管辖权的人民法院提起诉讼 |
| 7 | 中 | 付款周期不合理 `R-PAY-002` | 收到发票后 60 个自然日内付清（阈值 30 日） |
| 8 | 中 | 合同自动续约风险 `R-TERM-001` | 服务期满后如双方均无异议则自动续约一年 |

**步骤 8 —— 回写评论结构**

评论正文约 3500 字符，固定六段：

```
【智能合同审查意见（系统自动生成 · 仅辅助人工审批）】

一、合同基本信息      审批编号 / 合同标题 / 申请人 / 审查时间
二、总体风险等级      高（命中 8 条：高 3 / 中 5 / 低 0）
三、风险明细          逐条：等级 + 规则名称 + 规则编码 + 命中证据 + 证据位置 + 处理建议
四、审批关注点        12 条关键要点清单
五、风险摘要          中文综合分析结论
六、说明              本意见由系统自动生成，仅辅助人工审批，不替代人工审核决策
```

### 验证回写真实到达审批系统

```powershell
curl "http://127.0.0.1:9100/api/_comments/HTSP20261009002"
```

预期返回中包含 `CMT-HTSP20261009002-1`，即审批系统评论区实际收到的审查意见。

## 四、调用端页面分步操作

浏览器打开 <http://127.0.0.1:8000/> ，页面**严格覆盖五大模块**：

### ① 待办调用模块

1. 左侧导航点「**待办调用**」；
2. 拉取条数保持 `10`，点「**拉取待审审批单**」→ 列出 8 条待办，含审批编号 / 标题 / 申请人 / 申请时间 / 附件数量；
3. 点「**拉取并去重入库**」→ 提示 `新建 8 / 更新 0 / 去重跳过 0`；**再点一次** → 提示 `新建 0 / 去重跳过 8`，**直观验证去重**；
4. 点「**一键闭环（拉取→审查→回写）**」→ 全量走完闭环，输出结果总表。

### ② 详情查看模块

1. 点任意待办行的「**查看详情**」，或左侧导航进「**详情查看**」输入审批编号；
2. 页面展示：审批基础信息、表单数据、**附件信息表**（附件编号 / 文件名 / 类型 / 大小 / MD5 / 下载状态 / 本地存储路径）；
3. 点附件行「**下载**」→ 调用工具 3，刷新可见 `download_status` 变为「已下载」并展示 MD5；
4. 若该审批单未入库，页面会提示并提供「一键执行本任务闭环」。

### ③ 解析结果模块

1. 「文档标识」自动填充为 `attach:<附件ID>`（也可输入审批编号）；
2. 点「**解析文档**」→ 展示 16 项字段卡片，**每张卡片包含**：
   - 字段值（未提取到时显示占位值「未识别」并标红）
   - 原文片段（**证据原文高亮块**）
   - 📍 内容位置定位（`第X页 第B段 第L行（字符偏移 s-e，来源：…）`）
   - 提取方式与**失败原因**
3. 顶部展示完整度 `14 / 16（88%）`、页数、字符数、OCR 引擎。

### ④ 规则命中模块

1. 点「**执行规则审查**」；
2. 顶部五张统计卡：总风险等级 / 命中规则总数 / 高风险数 / 中风险数 / 低风险数；
3. 下方逐条风险卡片：**风险等级标签 + 规则名称 + 规则编码 + 命中证据原文 + 内容位置 + 标准化处理建议**；
4. 底部展示风险摘要与审批关注点清单。

### ⑤ 结果处理模块

1. 点「**保存审查结果**」→ 提示 `review_id`，展示保存状态、命中统计、风险摘要、关注点；
2. 点「**回写审批评论**」→ 展示回写状态（`success`）、HTTP 码、审批系统响应原文；
3. 页面底部「**最终输出内容**」区域展示回写至审批系统的评论全文，可一键复制；
4. 「**回写日志**」表格展示每次回写的状态与响应；
5. 「**任务执行日志**」展示全链路留痕。

### 附加模块

| 模块 | 用途 |
| --- | --- |
| 系统总览 | 任务数、状态分布、风险分布、启用规则数、命中总数看板 |
| 阻塞重试 | 列出全部阻塞任务与阻塞原因，支持单条 / 批量人工重试 |
| 规则管理 | 16 条内置规则全览，支持启用 / 停用 |
| 运行日志 | 按任务 ID / 级别 / 类型过滤查询全链路日志 |

## 七、异常恢复演示（人工重试）

演示脚本的步骤 10 会自动完成下面两个演示；也可按下述命令手工操作。

### 演示 A：外部接口调用失败 → 恢复

```powershell
# 1) 取一个已完成任务（任务 4）准备重跑
#    先把模拟审批系统切为「不可用」
curl -X POST "http://127.0.0.1:9100/api/_simulate/offline?value=1"

# 2) 管理员重试 → 因接口不可用而阻塞
curl -X POST "http://127.0.0.1:8000/api/admin/retry/4?operator=系统管理员-演示"
#    预期：task_status = blocked，block_reason = 外部接口调用失败，retry_count = 1

# 3) 恢复模拟审批系统
curl -X POST "http://127.0.0.1:9100/api/_simulate/offline?value=0"

# 4) 再次重试 → 成功闭环
curl -X POST "http://127.0.0.1:8000/api/admin/retry/4?operator=系统管理员-演示"
#    预期：task_status = done，write_status = success，retry_count = 2
```

**演示要点**：接口故障被完整捕获，任务**不崩溃**，转入 `blocked` 并记录具体原因；
故障恢复后重试可回归 `parsing → reviewing → done` 完整闭环。

### 演示 B：附件缺失 → 补传附件 → 重试成功

```powershell
# 1) 申请人补传附件（模拟审批系统提供该演示接口）
curl -X POST "http://127.0.0.1:9100/api/_simulate/add_attachment?instance_id=HTSP20261009005&file_name=采购合同-标准版.docx"

# 2) 管理员重试 → 系统自动重新拉取审批单详情，同步到新附件，走完闭环
curl -X POST "http://127.0.0.1:8000/api/admin/retry/5?operator=系统管理员-演示"
#    预期：task_status = done，attachment_count = 1，overall_risk_level = 低
```

**演示要点**：重试前系统会**重新拉取审批单最新详情**并同步附件清单 ——
否则「附件缺失」类阻塞永远无法恢复（本地附件清单会停留在首次拉取时的状态）。

### 演示 C：批量重试

```powershell
curl -X POST "http://127.0.0.1:8000/api/admin/retry_batch" ^
  -H "Content-Type: application/json" ^
  -d "{\"task_ids\":[6,7,8],\"operator\":\"系统管理员\"}"
```

**预期**：任务 6/7/8 重试后**仍保持阻塞** —— 因为原始材料本身不可用（无 OCR 组件 / 空白 / 损坏），
系统不做猜测性结论。这恰好验证了「不降级、不臆断」的设计原则。

## 九、常见问题

**Q1：`python` 命令不可用 / 报 exit code 49？**
这是 Windows 应用商店的占位程序。请使用虚拟环境中的解释器：`.\.venv\Scripts\python.exe`。

**Q2：依赖装不上？**
加国内镜像：`--index-url https://pypi.tuna.tsinghua.edu.cn/simple`

**Q3：端口被占用？**

```powershell
$env:APP_PORT = "8100"; $env:MOCK_PORT = "9200"
$env:APPROVAL_BASE_URL = "http://127.0.0.1:9200"
.\.venv\Scripts\python run.py
```

**Q4：扫描件任务一直阻塞「扫描件图片无法识别」？**
说明当前环境无可用 OCR 组件。三选一：
1. 安装 Tesseract-OCR（勾选 `chi_sim` 中文语言包）+ `pip install pytesseract`；
2. `pip install paddleocr`；
3. 为图片提供同名伴随文本 `<图片名>.png.ocr.txt`（演示环境已为
   `软件开发合同-扫描件.png` 提供该文件，因此任务 3 可正常识别）。

**Q5：想重新演示一遍？**

```powershell
# 一键重置（业务数据 + 模拟审批系统数据）
.\.venv\Scripts\python scripts\demo_closed_loop.py --reset

# 或分开重置
curl -X POST http://127.0.0.1:8000/api/demo/reset          # 业务数据（保留规则配置）
curl -X POST http://127.0.0.1:9100/api/_simulate/reset     # 模拟审批系统数据
```

**Q6：演示脚本提示连接失败？**
请确认 `run.py` 的终端窗口仍在运行，且 `http://127.0.0.1:8000/api/health` 可正常返回。

**Q7：如何换成真实审批系统？**
只需改环境变量，代码零改动：

```powershell
$env:APPROVAL_BASE_URL = "http://真实审批系统网关:端口"
$env:APPROVAL_TOKEN    = "真实访问令牌"
.\.venv\Scripts\python run.py
```

对接所需的 4 个接口说明见 [工具调用说明文档 · 附录 A](工具调用说明文档.md#附录-a对接真实审批系统)。
